# 领域边界

管理县域改革试点、跨域承诺、评估证据和制度复制版本。

现有领域资料围绕以下边界组织：

- 试点目标与基线
- 跨域承诺
- 承诺重排
- 评估证据
- 经验版本与发布封存
- 本地化偏差与采用审批
- 报送受理、复核与中断恢复

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

## 角色与职责分离

| 角色 | 职责 |
| --- | --- |
| 省级发展改革部门 `province` | 建档、发布经验、重排承诺、受理报送、审批采用 |
| 县级试点单位 `pilot` | 申报方，只能补充材料（条款、风险、佐证），不能确认成效、不能发布 |
| 跨域合作伙伴 `partner` | 承担资金资源承诺，伙伴退出时须指定承接单位 |
| 独立评估人员 `evaluator` | 唯一的成效确认角色；可登记复核结论；可查看企业敏感数据 |
| 经验接收地区 `receiver` | 提交采用申请、本地差异与补偿措施 |
| 系统 `system` | 中断恢复、代办清点，不参与业务判定 |

企业敏感数据仅向省级与独立评估人员展示原值，其余角色看到脱敏占位并附提示。

## 核心规则

1. **连续档案**：五类引领区档案包含目标、基线指标（口径＝范围/来源/频率）、牵头与协同单位、制度条款、资金资源承诺、里程碑、风险和评估证据，按事件脉络串联。
2. **发布封存**：发布经验必须列明前置条件、明确的不适用范围，且引用的证据已经独立确认；发布时把数据口径、前置条件、不适用范围整体快照并封存摘要，后续补充不改版本。
3. **承诺可重排、评估不可改**：伙伴退出（须指定承接单位）或项目延期只能调整未履行承诺/未达成里程碑；已履行承诺和已纳入完成评估的承诺锁定。已确认证据与封存版本在任何重排后原值保留。
4. **矛盾指标单独复核**：新证据与已确认证据（同指标、同期、不同值）冲突时，登记复核单（CF-编号），原确认值不变；复核结论单独记录，不回写原证据。
5. **重复报送沿用原记录**：相同报送（同引领区、报送方、标题、内容的规范摘要）只首次受理，再次出现登记为去重事件并指回原受理序号。
6. **中断恢复**：服务重放哈希链台账，末尾半行残写截除，中间记录损坏或断链直接报篡改；恢复时清点到期未履行承诺、逾期里程碑、在办督办并登记恢复事件，同状态重复恢复去重。
7. **采用审批可追溯**：接收地区申请必须提交本地差异（无差异也要显式声明）及对应补偿措施；审批须逐项核对封存版本的全部前置条件；每项差异要么有补偿、要么有明确同意人。审批卡片直接展示采用版本与封存摘要、各前提满足情况、各差异的补偿措施或同意人，以及不适用范围。
8. **结论不可改写**：采用审批一旦作出即锁定，重复审批被拒绝。

## 台账与事件

服务以只增事件台账（JSONL）落地，事件信封契约见 `contracts/journal.schema.json`：

- 每条事件含连续序号、时间、提交人、角色、类型、载荷、前条摘要与本条 SHA-256 摘要；
- 事件即时 fsync 落盘；打开时全链校验，序号不连续、断链、摘要不符均按篡改处理；
- 领域事件类型：`zone.registered`、`profile.supplemented`、`submission.received`/`deduplicated`、`experience.published`、`plan.rearranged`、`commitment.fulfilled`、`evaluation.confirmed`、`metric.conflict.flagged`、`metric.review.recorded`、`supervision.opened`/`closed`/`restored`、`adoption.applied`/`decided`。
