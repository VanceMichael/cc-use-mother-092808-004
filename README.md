# 县域试点经验复制与偏差说明

管理县域改革试点、跨域承诺、评估证据和制度复制版本。

## 参与方与事实

主要参与方包括省级发展改革部门、县级试点单位、跨域合作伙伴、独立评估人员、经验接收地区。领域资料记录以下已经确认的事实：

- 嘉善将建设五个引领区
- 目标是把试点经验转化为可复制可推广制度成果
- 跨省通办、生态协同和前置货站体现制度与项目协同

## 业务约束

- 试点目标与基线
- 跨域承诺
- 评估证据
- 经验版本
- 本地化偏差

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/news_context_004.py` 负责读取和校验这些资料。

## 县域试点与制度转化服务

`src/pilot_transfer/` 在领域资料之上实现业务服务：

- `models.py`：引领区、档案节点、跨域承诺、评估、经验版本、受理记录、复核事项、采用申请与批复的数据结构，全部可以落盘还原；
- `store.py`：单文件 JSON 快照存储，临时文件加原子替换，中断后从快照恢复；
- `service.py`：业务规则的唯一入口；
- `errors.py`：`PermissionDenied`（角色越权）与 `RuleViolation`（违反领域规则）。

服务强制的规则：

1. 五类引领区各自建立连续档案，目标、基线指标、牵头与协同单位、制度条款、资金资源承诺、里程碑、风险、评估证据八个部分每次修订都形成新的链条节点，历史节点只增不改；
2. 经验发布必须基于已确认评估，并封存数据口径、前置条件和明确的不适用范围，版本只增不减，封存后不可改写；
3. 伙伴退出或项目延期只能重排未履行承诺，原承诺保留并标记已重排，新承诺记录重排原因与经办人；已履行承诺不得变动，已完成评估不得改写；
4. 申报方只能补充评估材料，成效确认只能由独立评估人员完成；
5. 企业敏感数据按接收者职责展示：评估与督导角色和材料提交方可见原文，其余角色只见脱敏内容；
6. 相同报送再次出现时沿用原受理记录，不重复建档；
7. 与基线或已受理口径矛盾的指标不并入台账，单独进入复核队列，由省级督导或独立评估人员办结；
8. 每次变更即时落盘，进程中断重启后恢复督办视图：到期未履行承诺、待复核指标、待审批采用申请；
9. 接收地区申请采用制度时必须提交本地差异和补偿措施；审批要求封存版本中的每条前置条件要么已满足、要么有明确同意人的偏差记录，批复直接写明采用的是哪一版经验、哪些前提已经满足、哪些偏差获得了谁的同意，覆盖不全的申请退回并说明。
